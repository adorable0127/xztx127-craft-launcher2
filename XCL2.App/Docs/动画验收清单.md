# 动画与窗口透明验收清单

本清单用于在 Windows 上运行重新编译的 XCL2 后验收。源码的 XML 与静态检查不能替代 Windows WPF 编译、真实窗口合成或视觉流畅度验证。

## 验收准备

1. 使用 Windows 10 / 11 和 .NET 8 SDK，在源码根目录执行 `dotnet build XCL2.App.csproj -c Release`，记录构建结果。
2. 在桌面放置浅色、深色和有明显纹理的背景，便于确认整窗透明是否真正透出窗口后面的内容。
3. 先使用默认设置（总动画速度 75%、全无动画模式关闭），再分别测试所有动画关闭、单项关闭、强度为 0、25、50、100、低性能模式和全无动画模式。保存后退出并重新启动，确认偏好持久保存。
4. 窗口测试每种操作至少重复 10 次；快速切换测试连续操作 20 次。建议在 60 Hz 和高刷新率屏幕上分别观察；需要量化时录屏并逐帧检查。
5. 使用 `--no-animation` 参数启动一次，确认所有分类静态显示；随后正常启动，确认保存的动画偏好未被临时参数覆盖。

## 页面加载与二级切换回归

1. 在速度 75% / 100%、强度 100% 下，依次打开首页、版本、模组、设置、下载、服务端和百宝箱。加载层先出现“正在加载”，目标页只入场一次；无“占位刚滑入又重播”、内容先闪现再消失或长时间半透明。
2. 准备包含大量版本及 JAR 的测试目录，进入版本/模组页后立刻切到别页，再回去。旧请求不覆盖当前目录；窗口和侧边栏仍能响应。分别安装/重命名实例后，在扫描完成前切到含同名实例的另一目录，选择不得跳到错误实例。
3. 在下载类别、服务端类别、资源详情/返回、百宝箱标签间反复切换。父子动画不叠加，列表与目标标题一致；快速改变核心类型或来源时，旧网络回包不覆盖新选项。
4. 服务端实例读取期间最小化、收到托盘再恢复，加载应正常恢复完成，不永久停在“正在读取服务器信息”。
5. 打开快速开始向导，在扫描期间连续切来源、目录、上一步及关闭；加载中不允许用旧版本继续，关闭后不回弹旧窗口或错误提示。既有配置目录失效时，版本页选择有效目录后可正常启动。
6. 检查设置字体下拉首次展开/再次展开、Java 自动探测、开页备份，以及手动检查前置模组；加载期间不改变当前选项，离页后的结果不弹回。
7. 开启完全无动画模式：所有加载位置保留静态轨道与“正在加载”；切换任一优化策略、取消导航或直接关闭程序后，无残留加载层、计时器或不可点击页面。
8. 在 Windows 编译后用任务管理器和录屏观察帧率、UI 响应及内存；至少测试 100%、150%、200% DPI。源码静态检查不替代这一实机步骤。

## 总速度与效果强度

总速度和分类强度是两个独立设置。以下测试固定其它条件，每次只调整一项；启用“显示界面帧率”或使用录屏辅助观察。

| 调整项 | 对照操作 | 验收结果 |
| --- | --- | --- |
| 默认总速度 75% | 切换页面、打开窗口、从任务栏恢复、显示通知 | 页面与窗口过渡清晰可见，通知具有滑入与淡入；点击文字仍只有轻描边，纸娃娃攻击和受击仍轻。 |
| 总速度 25% / 75% / 100% | 同一类别强度固定为 100，重复同一操作 | 动作幅度相同；25% 耗时为默认 75% 的约 3 倍，100% 耗时约为默认的 0.75 倍。速度越大，完成越快。 |
| 分类强度 25% / 100% | 总速度固定为 75%，重复同一操作 | 位移与淡入幅度改变，过渡耗时保持一致；降低强度不会同时加速动画。 |
| 分类强度 0% | 速度保持 75%，执行该类别操作 | 该类别直接完成；其它类别继续按各自设置播放。 |
| 播放时改变总速度 | 过渡途中调节滑块，随后再次触发相同操作 | 当前过渡安全收尾；新过渡使用新速度，关闭和收起操作没有丢失。 |
| 手动保存 / 放弃修改 | 修改速度及分类强度后，分别保存或放弃并离开设置页 | 保存值可跨重启恢复；放弃后立即恢复已保存值，预览不遗留。 |
| 受击事件与总速度 | 在不同速度下选择“被攻击” | 受击动作及其闪光保持实际时间节奏；每次浅红滤镜实际显示时间仍少于 100 ms，不随减速拉长。 |

## 全无动画模式与优化策略

| 场景 | 操作 | 验收结果 |
| --- | --- | --- |
| 默认状态 | 新配置启动并打开设置页 | 全无动画模式默认关闭、策略默认全能模式；默认页面、窗口、通知动画仍可观察。 |
| 开启全无动画模式 | 勾选对应开关 | 显示“这会降低 CPU 以及内存的占用，但是可能会变得有视觉污染”，并展开内存优先、CPU 优先、全能模式选项；初始化回显已保存设置不重复弹提示。 |
| 无动画模式开启 | 依次触发 15 类动画及快速切换窗口状态 | 直接执行最终状态，没有动画队列、残留遮罩或不再响应的控件。 |
| 模式退出 | 关闭全无动画模式 | 先前的总速度、每类开关与强度恢复，不被模式临时改写。 |
| 内存优化策略 | 来回切换“更多”和“鸣谢与帮助”页，并更换背景 | 不额外缓存展示页；移除背景位图缓存；GIF 保留独立静态帧，视频解码表面关闭；再次打开可正常重建。 |
| CPU 优化策略 | 重复访问“更多”和“鸣谢与帮助”页、重复使用相同静态背景 | 最多复用这两页，背景使用位图缓存；恢复页后正常操作，主题和语言仍正确。 |
| 全能优化策略 | 交替访问两个展示页并导入不同静态背景 | 最多保留一页，旧页面会被淘汰；背景缓存分辨率为 75%，旧条目不会无限累积。 |
| 改变策略 | CPU → 内存 → 全能，分别保存或放弃 | 新策略立即按当前预览生效；旧缓存按策略清理；放弃后回到已保存策略。 |
| 视频策略切换 | 无动画 + 内存优先时，切换到 CPU 优先 / 全能模式 | 视频背景重新装载为静止画面，保持不播放；不用先保存或退出无动画模式才恢复。 |
| 隐藏 / 最小化 / 托盘 / 关闭 | 使用 GIF 或视频背景时执行这些操作 | 后台不持续运行可见性相关的动画、视频播放或 GIF 计时器；恢复后按当前模式继续显示。 |
| 缓存生命周期 | 在缓存模式下反复回到首页和百宝箱 | 语言切换、主题、访客/简洁模式和内存监测仍正常；事件与计时器无重复绑定或永久停用。 |
| 取消导航 | 从未保存设置页点首页或其它导航，在提示中选择重新编辑 | 留在原设置页；未展示的新页面不留下静态事件订阅或计时器；快速改点其它入口不再构造旧目标页。 |
| 退出程序 | 在缓存模式下关闭启动器 | 页面缓存、背景帧和渲染回调被释放，没有为缓存额外保留的后台窗口。 |

若触发愚人节整蛊，窗口乱移动、按钮躲避和磁贴乱跳也应尊重动画总开关、低性能模式及全无动画模式；禁用后复位，首页离开、窗口隐藏或最小化时停止相关动画计时器。

优化策略的内存与 CPU 结果需在同一台机器、同一批页面与背景下对照观察。记录任务管理器的进程内存、CPU，以及首次访问与重复访问的响应差异；单次瞬时数值不能作为性能结论。

## 窗口状态与生命周期

| 起始状态 | 操作 | 验收结果 |
| --- | --- | --- |
| 正常窗口 | 最小化到任务栏，再从任务栏恢复 | 连续播放过渡；内容不在旧尺寸停住一帧；恢复后完整显示，无残留缩放、位移或透明度。 |
| 最大化窗口 | 最小化，再恢复 | 恢复至最大化；标题栏、侧栏和内容完整，边缘无闪白、黑块或裁切。 |
| 正常窗口 | 最大化，再还原 | 位置和尺寸正确；无旧画面截图叠加、跳动或单帧冻结。 |
| 正常窗口 | 进入全屏，再退出全屏 | 进入和退出均响应；退出恢复此前位置、尺寸和状态。 |
| 最大化窗口 | 进入全屏，再退出全屏 | 退出后恢复最大化，不误变为正常窗口。 |
| 任意窗口 / 多屏不同 DPI | 在各显示器进入和退出全屏 | 全屏使用当前显示器完整范围；普通最大化避让任务栏；退出后正常窗口位置、尺寸正确。 |
| 正常 / 最大化 / 全屏 | 收到系统托盘，再从托盘恢复 | 还原到预期状态；主窗口可操作，无透明遮挡层或遗留缩放。 |
| 正常窗口 | 打开 / 关闭主窗口 | 开关响应正常；关闭动画结束后进程按关闭设置执行，动画禁用时无需等待过渡。 |
| 任意状态 | 快速交替最小化、恢复、最大化、全屏、还原 | 最后一次操作决定最终状态；没有排队播放旧动画、重复关闭、输入失效或残留遮罩。 |
| 过渡正在播放 | 在设置中关闭总开关或启用低性能模式 | 动画停止并落到稳定显示状态；控件仍可操作，无半透明或半缩放的残留。 |

## 分类动画、强度与低性能模式

逐行测试：该项启用且强度为 100 → 强度为 25 → 强度为 0 → 关闭该项。强度减小应只让效果更轻，不造成布局错误或控件失效；0 和关闭均不播放该项动画。

| 动画分类 | 触发操作 | 观察要点 |
| --- | --- | --- |
| 窗口打开 | 启动和打开受支持窗口 | 无额外卡顿；结束后透明度匹配当前设置。 |
| 窗口最小化 / 收到托盘 | 标题栏最小化、收到托盘 | 过渡自然收尾后执行窗口操作，没有停在半透明状态；动画关闭时直接执行。 |
| 窗口恢复 / 从托盘还原 | 任务栏和托盘还原 | 不先闪现旧尺寸画面。 |
| 窗口最大化 / 全屏切换 | 最大化、还原、进入 / 退出全屏 | 结束后位置、尺寸、缩放与透明度正确。 |
| 窗口关闭 | 关闭窗口或弹窗 | 操作仍完成；关闭动画禁用后立即执行。 |
| 页面切换 | 快速切换左侧多个页面 | 无黑屏、闪白、旧页面重复出现或输入延迟。 |
| 弹窗 / 抽屉 | 连续打开、关闭弹窗与抽屉 | 遮罩与内容同步；动画被关闭时遮罩也不留在屏幕上。 |
| 侧边栏展开 / 收起 | 连续展开和收起侧栏 | 不积压动画；最终宽度和内容裁切正确。 |
| 按钮 / 文字点击反馈 | 点击带文字按钮、导航和链接 | 反馈轻微；文字本身没有大幅明暗闪烁、缩放模糊或突然消失。 |
| 通知提示 | 连续触发多个通知 | 通知可正常显示和消失；禁用动画仍保留必要提示与关闭操作。 |
| 加载指示 | 打开需要等待的页面、下载和安装界面 | 加载圆点或进度提示的动画可以关闭；提示内容仍显示；切页后旧指示不继续消耗渲染资源。 |
| 平滑滚动 | 鼠标滚轮、触控板、滚动条拖动 | 无积压或滚动回弹；禁用后使用直接滚动，最终位置正确。 |
| 3D 皮肤日常动作 | 站立、走动、疾跑 | 降低强度后幅度相应减小；关闭后静止，拖动旋转和缩放仍可操作。 |
| 3D 皮肤攻击动作 | 选择“攻击” | 攻击幅度轻，不出现大幅甩臂；强度与单项开关生效。 |
| 3D 皮肤受伤动作 / 红色闪光 | 选择“被攻击” | 受击幅度轻；浅红滤镜只覆盖模型，持续不到 100 ms；强度与单项开关生效。 |

另行检查：关闭动画总开关、启用低性能模式后，上表所有类别均停止；退出低性能模式或重新打开总开关后，各类别恢复各自保存的启用状态和强度。无关动画的单项设置不应改变其它类别。

## 强度滑杆回归

- 分别将“页面切换”的强度设为 100%、25%、0%，观察行内预览；默认速度 75% 时，前两者应仍为 320 ms，而起点位移分别为 18 px、4.5 px，起点不透明度分别约为 0、0.75；0% 静止。保存后切主页面及二级页面，效果应与所选强度一致。
- 对常用窗口、弹窗、侧栏逐行拖动并点击“预览”，确认只演示行内目标，主窗口不会被预览按钮真正关闭或最小化。快速拖动只播放最后一次值；离开设置后无延迟播放。
- 打开自动保存，观察预览播放期间的保存提示：同一数值保存不应截断正在播放的预览。手动保存、离页选择保存、撤销和重启后分别检查数值及实际效果。
- 通知强度设为 25% 与 100%，分别触发通知显示、自动消失、拖动关闭及短距离拖动回弹，确认自动位移和明暗幅度不同，最后均正常移除或归位。0% 立即收尾。
- 修改通知等无关分类的强度时，不应结束尚在播放的页面过渡；关闭总开关、启用完全无动画模式则应立即归位，预览保持静止。

以上为 Windows 实机待执行的验收步骤，不代表已完成运行测试。

## 透明度与文字

| 设置组合 | 操作 | 验收结果 |
| --- | --- | --- |
| 仅开启面板透明 | 面板透明度从 100 调至 60 | 面板颜色变化；文字仍清晰；整窗透明开关有独立效果。 |
| 仅开启全局窗口透明 | 整窗透明度从 100 调至 80、50 | 标题栏、文字、按钮与背景一起变透明，能看见窗口后方桌面；滑块不只是修改面板颜色。 |
| 两种透明同时启用 | 分别调节两个滑块 | 两种设置各自生效；无动画把整窗透明度错误恢复到 100%。 |
| 全局窗口透明启用 | 最小化 / 恢复 / 最大化 / 全屏 / 托盘恢复 | 每次过渡结束后仍使用保存的整窗透明度。 |
| 弹窗 / 抽屉使用独立外观 | 打开对应 UI，调节独立透明度 | 与主窗口的外观配置一致地叠加；关闭弹窗后主界面透明度正确。 |
| 关闭两种透明 | 保存并重启 | 窗口正常显示，没有残留整窗透明或临时动画值。 |
| 低性能模式开 / 关 | 分别调节全局透明度并保存 | 透明度按界面显示的设置生效；没有假启用、滑块无效果或退出模式后突然跳变。 |

## 3D 纸娃娃与资源释放

- 使用默认 Steve、Alex 和自定义皮肤分别观察攻击与受击，确认材质、UV 和模型均正常。
- 受击浅红滤镜应是短促的模型内效果，背景、按钮和说明文字不染红。使用高帧率录屏检查单次显示时间少于 0.1 秒；任意时刻切换动作或关闭动画后不留下红色。
- 关闭纸娃娃、切换到其它页面、最小化主窗口后观察进程资源；不可见模型不应继续维持渲染回调。重新打开后动作正常恢复。
- 动画正在播放时改变强度或总开关，确认模型立即采用新设置，无旧动作继续累计、复位跳动或不可拖动问题。

## 验收记录

记录 Windows 版本、显卡及驱动、屏幕刷新率、源码版本、构建日志和失败的矩阵行。静态检查通过仅表示已检查的结构或引用未发现问题，视觉卡顿是否消除以本机运行结果为准。
