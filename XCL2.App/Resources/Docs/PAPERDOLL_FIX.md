# XCL2 解决方法与修复说明

本文件记录使用方式和问题处理。API 的参数、返回值和接入示例单独放在 `API_REFERENCE.md`。

## 本轮：崩溃日志误判与内置帮助文档

### 崩溃页面把正常日志当成崩溃

原先扫描代码无条件将每个实例的 `logs/latest.log`、`logs/debug.log` 加入崩溃列表，然后执行崩溃分析规则。正常运行、菜单退出和手动结束游戏都会留下这些文件，因此“发现日志文件”不等于“游戏发生崩溃”。

现在的使用方法：

1. 打开“日志”，勾选“显示日志面板”，进入“崩溃报告分析”。
2. “显示正常日志”开关默认关闭。关闭时只列出 Minecraft 的 `crash-reports/*.txt`、JVM 的 `hs_err_pid*.log` 和启动器记录的已确认异常退出快照。
3. 需要阅读正常运行、正常退出、手动关闭或退出情况无法确认的普通日志时，打开“显示正常日志”。普通文件有单独标签，不会自动执行崩溃规则；将这类日志交给 AI 时也明确告知“未确认崩溃”。
4. 再次关闭开关会立即重新筛选，并清除不再可见的普通日志原文和结论。开关设置会保存，首次使用和旧配置缺少此字段时均为关闭。
5. 没有生成原生崩溃报告的异常启动退出，会保存为实例目录 `logs/xcl2-crashes/exit-*.log`；后续正常启动覆盖 `latest.log` 不会删除这份快照。它记录本次退出码、时间和日志证据。

分类沿用并收紧了进程退出判断：启动器主动关闭、退出码为 0、Windows 控制台关闭终止码和没有明确崩溃证据的疑似人为退出，不生成崩溃快照。单独的 INFO/WARN/ERROR、普通 `Caused by:` 或无证据的非零退出码不作为确定崩溃的依据。

旧版本留下的普通日志没有可靠的退出记录；不会仅凭它存在就补判为崩溃。要查看这类历史文件，可打开“显示正常日志”。启动器未运行时发生的退出，也只能依据实际留下的 Minecraft/JVM 崩溃报告显示，不能保证还原退出原因。

### 帮助 MD 在哪里，如何拉取

入口：“鸣谢与帮助 → 帮助文档（离线可用）”。

- “解决方法与修复说明”：本文件 `PAPERDOLL_FIX.md`，保留既有纸娃娃、皮肤和离线头像处理说明。
- “启动器 API 接入说明”：`API_REFERENCE.md`，只解释 DLL 插件、配置/日志、EXE 进程约定、命令行、自定义 AI 服务、宿主管理和内置文档读取接口。
- 两份文档各有“查看”和“导出 MD…”按钮。查看在启动器内完成，不需要外部 Markdown 软件；导出时选择本地保存位置。
- 根目录各保留一份 MD；项目内 `XCL2.App/Resources/Docs/` 各保留一份 MD。项目内的副本作为 `EmbeddedResource` 编入程序集，运行时从程序集读取，不依赖源码包外的文件或网络。
- 原有 `PLUGIN_GUIDE.md` 也保留根目录和项目内副本，插件管理中的原有指南按钮继续使用兼容资源名。
- 维护时同步根目录与项目内副本，编译后更新内置文档。MD 读取与导出代码接口见 `API_REFERENCE.md` 第 8 节。

## 上轮：皮肤清晰度

用户实机反馈确认模型显示正常，但眼睛、脸部和衣服的像素被明显平滑。

- 新增 `PreparePixelTexture`：将 64×64 皮肤的每个像素复制成 32×32 的同色块，生成 2048×2048 显示贴图；128×128 等尺寸按对应整数倍处理。保留原色、透明度和宽高比，不进行插值，也不改写用户原始皮肤文件。
- 整数倍扩展减少 3D 采样时颜色过渡占据的范围，保留 Minecraft 的像素块外观；不能仅依靠画刷上的 `BitmapScalingMode` 设置。
- 默认/本地皮肤、微软账户在线皮肤和皮肤站在线皮肤均使用相同处理。在线贴图在后台处理，完成后再更新材质。
- 扩展后的单张 BGRA 像素缓冲最多为 16 MiB；无需扩展的高清皮肤直接复用。处理只在加载皮肤时进行，不在动画帧中重复计算。
- 同时对视口设置最近邻缩放。此前修正的绝对 UV 坐标和自动取景保持生效。

## 修复内容

修改文件：`XCL2.App/Views/SkinModelViewerDialog.xaml.cs`。

- 修正皮肤图集的坐标映射：`ImageBrush` 使用 `ViewportUnits = Absolute`，并固定 `Viewport = (0, 0, 1, 1)`。原来的默认相对映射会把整张皮肤重新缩放到各个身体部件的 UV 范围，误采样其它部位和透明留白，造成截图中的错位、重复和碎裂外观。
- 本地皮肤和异步加载的在线皮肤共用修正后的画刷；在线替换图片时仍保持正确的映射。
- 相机根据视口宽高比自动计算默认距离，给身体和四肢运动留出空间，修复默认视角下脚部被裁切的问题。视口尺寸变化时会重新适配，拖动旋转和滚轮缩放继续可用。
